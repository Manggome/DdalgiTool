# 기획서 ↔ 데이터 테이블 대조

기획서에 적힌 **수치·목록·규칙**이 데이터 테이블에 그대로 반영됐는지 본다.
문장 전체를 비교하지 않는다 — **대조할 수 있는 사실**만 뽑아 표로 만든 뒤 스크립트로 비교한다.

## 1. 기획서에서 사실 뽑기
대상 시스템의 기획서에서 다음만 뽑아 `[항목, 기획서 값, 원문 인용, 섹션]` 표로 만든다.
- 수치: 가격·보상량·확률·쿨타임·최대 레벨·개수 제한 ("패키지 A 가격 9,900원", "출석 7일차 보상 2배")
- 목록: 종류·등급·단계 ("등급은 일반/희귀/전설 3종")
- 규칙 중 데이터로 표현되는 것: 해금 조건 레벨, 구매 제한 횟수, 기간
서술형 규칙(연출·UX)은 여기서 다루지 않는다 (기획서↔코드 표본 점검으로).

## 2. 대응하는 테이블 찾기
설계 지도·카탈로그로 시스템 ↔ 테이블(탭)을 찾는다. 열 이름이 다르면 헤더를 보고 대응을 정하고,
애매하면 판정하지 말고 "확인 필요"로 둔다. 시트는 해당 열·행만 읽는다.

## 3. 비교 (스크립트)
- 값 다름: 기획서 9,900 ↔ 테이블 8,900
- 기획서에만 있음: 기획서의 "전설 등급" ↔ 테이블에 없음
- 테이블에만 있음: 테이블에 "신화 등급" 행 ↔ 기획서 언급 없음 (기획서가 오래됐을 수 있음 — 날짜 함께 표시)
- 단위·표기 차이(%, 초/밀리초, 원/USD)는 변환 후 비교하고, 변환했다고 근거에 적는다.

## 4. 판정 기록
항목마다: 종류(값 다름/기획서에만/테이블에만), 기획서 인용(문서·섹션), 테이블 위치(시트!셀), 심각도, 고칠 방향
("테이블을 기획서에 맞춤" / "기획서 갱신 필요" / "기획자 확인 필요").
어느 쪽이 맞는지 판단할 근거(최근 수정일, 슬랙 결정, 기록)가 있으면 함께 적는다.
