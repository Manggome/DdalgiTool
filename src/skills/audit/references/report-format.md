# 점검 보고서 형식 — `점검보고서_<범위>_<YYMMDD>.html`

공통 HTML 규칙(공통 지침)을 따른다. 혼자 열리는 한 파일, 위쪽 한눈 요약, 기술 근거는 접기.

## 구성
1. **한눈 요약** — 어긋남 총 n건 (상 n · 중 n · 하 n), 직전 점검 대비 🆕 새로 생김 n / ✅ 해결됨 n / 그대로 n,
   점검 범위(시스템 목록)와 점검하지 못한 것(연동 안 됨·매핑 없음)
2. **상 → 중 → 하 순 카드** — 카드 하나 = 어긋남 하나
   - 제목: 무엇이 어긋났나 (유저 관점 한 줄: "전설 패키지 가격이 기획서와 다름")
   - 종류 배지: 테이블↔코드 / 기획서↔테이블 / 기획서↔코드 / 트렐로↔실제
   - 상태 배지: 🆕 / 그대로 (해결된 것은 맨 아래 따로)
   - 양쪽 근거 (접기): 기획서 인용·문서 링크 / 시트!셀 / 파일:라인 / 카드 링크
   - 고칠 방향 + 담당 스킬 (📝 기획서 / 📊 데이터 테이블)
3. **확인 필요** — 한쪽 근거만 있거나 대응을 확신할 수 없는 것
4. **해결됨** — 직전 점검에 있었는데 이번에 없어진 것 (짧게)
5. **점검 방법** (접기) — 사용한 매핑 선언, 대조 스크립트 요약, 범위·제외 사유
6. 맨 위 필터 버튼: 전체 / 상 / 🆕만

## 비교 파일 `.ddalgi/audit/last.json`
```json
{
  "at": "2026-10-23T10:00:00Z",
  "scope": "전체",
  "items": [
    { "id": "doc-table:package-legend-price", "kind": "doc-table", "severity": "상",
      "title": "전설 패키지 가격이 기획서와 다름", "evidence": "기획서 3.2 9,900원 / Shop_Info!E14 8,900" }
  ]
}
```
- `id` 는 같은 어긋남이면 다음 점검에서도 같게 나오도록 **종류:대상:속성** 으로 만든다 (행 번호·날짜를 넣지 않는다).
- 비교: 이번에만 있음 = 🆕, 둘 다 = 그대로, 지난번에만 = ✅ 해결됨. 비교 후 이번 결과로 덮어쓴다.
