# 🗺 설계 지도 만들기·갱신 (design-map)

프로젝트의 시스템·재화·테이블·기획서·코드가 서로 어떻게 연결되는지 **설계 지도**로 만든다.
결과는 `.ddalgi/index/design-map.json` 에 저장되고, 사이드바 [🗺 설계 지도] 에서 그래프로 본다.
다른 스킬(찾기·영향, 점검, 밸런스)이 이 지도를 먼저 참고해 문서를 덜 읽는다.

## 언제 쓰나
처음 한 번, 그리고 시스템·테이블이 크게 바뀐 뒤.

## 꼭 지킬 규칙
1. **노드마다 출처**: 모든 노드에 실제 위치(문서 id·시트!탭·파일 경로)를 단다. 출처 없는 노드는 만들지 않는다.
2. **연결은 근거가 있을 때만**: 문서에 언급, 테이블 열 참조, 코드에서 사용, 매핑 선언 중 하나가 있어야 선을 긋는다.
3. **기존 지도 존중**: 갱신이면 `design_map_load` 로 기존 지도를 읽어 바뀐 부분만 고치고, 사용자가 손댄 메모(`note`)는 지우지 않는다.
4. **통독은 서브에이전트**: 시스템별로 나눠 맡기고 노드·연결 목록만 받는다.

## 절차
1. `design_map_load` — 기존 지도와 자동 생성 뼈대(카탈로그의 문서·시트 탭·매핑)를 받는다
2. 시스템 목록 잡기 — 카탈로그·기획서 목차로 시스템(예: 상점, 출석, 탐험)과 재화(골드·젬 등)를 정한다
3. 시스템별 조사 — 관련 기획서·테이블·코드를 연결 (서브에이전트)
4. `design_map_save` — 노드·연결 저장 (형식: `references/map-format.md`)
5. "사이드바 🗺 설계 지도에서 볼 수 있어요" 안내 + 요약(시스템 n개, 연결 m개, 새로 생긴 연결)

## 결과물
`.ddalgi/index/design-map.json` (사이드바에서 그래프로 표시).
