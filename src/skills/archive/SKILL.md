# 아카이빙 (archive)

의사결정을 ADR로 기록하고, 작업 로그를 축적하고, 슬랙 90일 제한에 대비해 중요 대화를 백업한다.

## 저장 위치 (project.yaml `archive.path` 기준, 기본 `archive/`)
- `archive/decisions/NNNN-<제목-kebab>.md` — ADR (전역 연번)
- `archive/logs/YYYY-MM-DD.jsonl` — 작업 로그 (일 단위 파일, append only)
- `archive/slack/<채널명>/YYYY-MM-DD-<주제-kebab>.md` — 슬랙 백업

## 절대 규칙
1. **로컬 기록은 자유, 팀 공유는 승인 후**: `archive/` 아래 파일 작성은 승인 불필요. 그러나 슬랙 게시·드라이브 업로드 등 팀에게 보이는 배포는 게시 내용 미리보기 → 사용자 승인 후에만.
2. **ADR은 근거와 함께**: 결정의 배경·대안·근거 출처(슬랙 스레드 링크, 문서, 회의)를 반드시 포함. 출처가 대화 맥락뿐이면 그렇게 명시.
3. **로그는 조용히**: 다른 스킬이 쓰기 작업(독스/시트/트렐로/슬랙/문서 생성)을 완료하면 그 사실을 로그에 1줄 append한다. 사용자에게 매번 알리지 않는다.

## 작업 유형

| 요청 | 절차 |
|---|---|
| ADR 기록 | 결정 내용·근거 수집(부족하면 질문) → 템플릿으로 작성 → 저장 → 파일 경로 보고 |
| 슬랙 백업 | 대상 스레드/기간 확인 → 조회 → md 저장(원문 보존, 발화자·시각 포함) |
| 과거 결정 조회 | `decisions/` 파일명·제목 grep → 해당 ADR만 읽고 인용 답변 |
| 작업 로그 조회 | 해당 날짜 jsonl만 읽기 (기간 집계는 스크립트로) |
| 팀 공유 게시 | 게시문 작성 → 미리보기 → 승인 → 슬랙/드라이브 게시 → 로그 |

ADR 템플릿·작성 요령: `references/adr-template.md`
로그 스키마·슬랙 백업 형식: `references/log-format.md`

## 능동 제안 (강요 금지)
대화 중 명확한 의사결정이 이루어졌다고 판단되면(수치 확정, 시스템 방향 결정, 스펙 변경) 턴 마지막에 "이 결정을 ADR로 기록해둘까요?" 한 줄로 제안한다. 같은 결정에 대해 두 번 묻지 않는다.
