# ADR 템플릿과 작성 요령

## 파일명
`archive/decisions/NNNN-<제목-kebab>.md` — NNNN은 기존 파일 최대 번호 +1 (디렉토리 목록으로 확인). 제목은 한글이면 로마자화하지 말고 핵심 영단어 또는 짧은 한글 그대로 사용 가능 (예: `0012-gacha-pity-100.md`).

## 템플릿

```markdown
# NNNN. <결정 한 줄 요약>

- 상태: 확정 | 제안 | 폐기(→ NNNN이 대체)
- 날짜: YYYY-MM-DD
- 결정자: <이름/직군. 대화 맥락상 불명확하면 사용자에게 확인>
- 관련: <관련 ADR 번호, 트렐로 카드, 기획서명>

## 배경
<이 결정이 왜 필요했나. 문제 상황 2~5문장>

## 결정
<무엇으로 정했나. 수치·규칙은 정확히. 애매한 표현 금지>

## 검토한 대안
- <대안 A>: <기각 이유>
- <대안 B>: <기각 이유>

## 근거·출처
- 슬랙 #채널 YYYY-MM-DD 스레드 <링크>
- <기획서명> N장 / <시뮬레이션 결과 요약과 스크립트 경로>
- (출처가 이 대화뿐이면) "딸기툴 대화 중 구두 결정 (YYYY-MM-DD)"

## 영향
<바뀌는 테이블·문서·코드. explore 영향도 분석을 돌렸다면 그 요약>
```

## 작성 요령
- **결정이 아닌 것은 ADR로 만들지 않는다**: 단순 작업 완료, 미확정 아이디어는 로그로 충분. ADR은 "나중에 왜?라고 물을 일"만.
- 필수 필드가 대화에서 확보 안 되면 (특히 결정자, 대안) 한 번에 모아 묻는다. 대안이 정말 없었으면 "대안 검토 없음(즉결)"이라고 쓴다 — 빈칸을 지어내지 않는다.
- 기존 결정을 뒤집는 결정이면: 새 ADR을 만들고 옛 ADR의 상태를 `폐기(→ 새 번호)`로 수정한다. 옛 파일 내용은 지우지 않는다.
- 저장 후 파일 경로를 보고하고, 팀 공유(슬랙 게시)를 원하는지 묻는다 — 게시는 미리보기·승인 절차.

## 슬랙 90일 대비 원칙
ADR의 근거가 슬랙 스레드뿐이라면, 링크는 만료된다 — 해당 스레드를 `archive/slack/`에 백업하고 ADR에는 링크와 백업 경로를 함께 적는다.
