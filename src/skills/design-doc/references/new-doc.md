# 새 기획서 작성 가이드 (양식 학습)

## 1. 참조 문서 선정
- 사용자가 양식/참고 문서를 지정했으면 그것만 사용한다.
- 지정하지 않았으면: 인덱스 카탈로그에서 같은 카테고리(시스템/콘텐츠/이벤트 등)의 최신 기획서 2~3개를 후보로 제시하고 사용자에게 고르게 한다.
- 후보 문서 통독은 서브에이전트로 격리한다. 서브에이전트 지시: "이 문서들의 (1) 섹션 구조(제목 계층) (2) 각 섹션의 역할 한 줄 요약 (3) 반복되는 표/포맷 패턴 (4) 문체 특징(존댓말 여부, 용어 표기)을 추출하라."

## 2. 구조 확정
- 추출된 구조를 목차 형태로 사용자에게 보여주고, 새 기획서에 필요한 섹션 가감을 확인받는다.
- 이 단계에서 내용 관련 핵심 질문(대상 시스템의 목적, 범위, 연관 시스템)을 한 번에 모아 묻는다. 초안 작성 중에 찔끔찔끔 되묻지 않는다.

## 3. 초안 작성
- 학습한 구조·문체·표 포맷을 따른다.
- 수치가 필요한 곳에 임의 수치를 넣지 않는다. 미정 수치는 `[TBD]` 또는 `[밸런스 작업 필요]`로 표기하고, 밸런스 스킬로 산출 가능함을 안내한다.
- 기존 시스템을 참조하는 문장에는 근거 문서명을 각주처럼 표기한다: `(참고: <문서명> - <섹션>)`.
- 예외처리 섹션을 반드시 포함하고, `exception-review.md` 체크리스트 중 해당 항목을 미리 채운다.

## 4. 미리보기 → 승인 → 생성 (반드시 양식 복제 방식)

**빈 문서에 처음부터 그리지 않는다.** doc_append + set_style/indent 로 조립하면 목록 글리프(●○■)·
폰트 위계·번호 제목이 양식과 달라진다. 서식을 100% 유지하는 절차:

1. **초안 전문을 채팅에 미리보기**로 출력하고 승인받는다 (마크다운, 생성 위치·문서 제목 포함).
2. **양식 문서를 drive_copy** 한다 — 이름에 '양식'이 든 문서(예: `CATISLAND_(피쳐) 문서 양식_…`)를
   drive_search 로 찾아 새 제목으로 사본 생성. 양식이 없으면 사용자에게 어떤 기존 문서를 틀로 쓸지 묻는다.
3. **사본 구조 파악**: doc_read 로 사본을 읽어 각 서식별 기준 문단(제목 줄, ● 예시 줄, ○ 예시 줄,
   ■ 예시 줄)의 문구를 확보한다.
4. **채우기 — 서식 상속이 핵심**:
   - 표지·제목·작성자: doc_replace 로 치환
   - 본문: **doc_insert_after** 로 "같은 서식의 기준 문단 뒤"에 삽입한다 —
     ● 내용은 ● 문단 뒤에, ○ 내용은 ○ 문단 뒤에. 새 문단이 기준 문단의 목록·중첩·폰트를 그대로 상속한다.
   - 섹션 제목(번호 목록 h1/h3)도 같은 급의 제목 문단 뒤에 insert_after 로 넣는다.
   - **앵커 문구가 여러 문단과 겹치면 `nth`(몇 번째 일치, 1부터)로 특정**한다 — 양식의 예시 줄은
     같은 문구가 ●·○·■ 에 반복되는 경우가 많다 (예: `시스템에 대한 설명`이 3곳).
   - 같은 앵커 뒤에 여러 번 삽입하면 나중 것이 위로 온다 — 한 앵커에는 **여러 줄을 한 번에** 삽입하는 편이 안전하다.
   - ○ 를 특정 ● 바로 아래에 붙이려면, ○ 예시 줄이 그 위치에 없을 수 있다 — 이때는 ○ 앵커(nth 로 특정)에
     삽입한 뒤 필요하면 doc_delete_paragraph / doc_set_indent 로 자리를 맞춘다.
5. **정리**: 남은 양식 예시 줄·플레이스홀더를 doc_delete_paragraph 로 제거한다.
6. doc_read 로 최종 확인(제목 계층 #·## 와 목록 - 중첩이 의도와 맞는지) 후 링크를 보고하고 작업 로그에 기록한다.

## 주의
- 참조 문서의 문장을 그대로 복붙하지 않는다. 구조와 포맷만 학습하고 내용은 새로 쓴다.
- 초안 분량이 매우 길면(약 10페이지 초과) 섹션 단위로 나눠 승인받는 것을 제안한다.
