# 기획서 작업 상세 절차

## (a) 읽고 답변

1. **대상 분류**: 인덱스 카탈로그에서 질문 키워드(시스템명, 콘텐츠명)와 일치하는 문서 후보를 뽑는다. 후보가 없으면 드라이브 폴더의 문서 목록(제목만)을 조회한다.
2. **범위 좁히기**: 후보 문서의 목차(제목 구조)만 먼저 가져온다. 질문과 관련된 섹션을 특정한다.
3. **부분 읽기**: 특정된 섹션만 읽는다. 문서가 짧으면(대략 2~3페이지 이하) 전체를 읽어도 무방하다.
4. **답변 작성**:
   - 질문에 대한 직접 답 → 근거 문단 blockquote 인용 → 출처 블록 순서.
   - 여러 문서가 서로 모순되면 모순을 그대로 드러내고 어느 문서가 최신인지(수정일 기준) 표시한다.
   - 기획서에 없는 내용을 추론으로 보충할 때는 "추론:" 접두어로 명확히 구분한다.

### 서브에이전트 격리 기준
- 문서 1개가 매우 길거나(약 3천 단어 초과), 3개 이상 문서를 통독해야 할 때.
- 서브에이전트에게: 문서 ID 목록 + 질문 + "관련 문단을 원문 인용으로 반환하라"는 지시를 준다.
- 메인 컨텍스트에는 인용문과 요약만 남긴다.

## (b) 수정

1. 수정 대상 문서·섹션을 특정하고 **현재 원문을 읽는다** (읽지 않고 수정 금지).
2. 수정안을 작성한다. 사용자가 의도를 모호하게 말했으면 수정안 작성 전에 되묻는다.
3. **diff 미리보기 출력** — 반드시 아래 형식:

   ```
   문서: <문서명> / 섹션: <섹션명>
   --- 변경 전
   <원문 문단>
   +++ 변경 후
   <수정 문단>
   ```

4. "이대로 반영할까요?"라고 묻고 명시적 승인(예/반영해줘 등)을 기다린다. 승인 전 쓰기 API 호출 금지.
5. 승인 후 반영하고, 반영된 결과(해당 문단)를 다시 읽어 확인한 뒤 완료 보고한다.
6. 수정 사실을 archive 스킬의 작업 로그 규칙에 따라 기록한다(문서 ID, 변경 요약, 시각).

### 수정 시 주의
- 승인받은 범위 밖의 문장은 건드리지 않는다(맞춤법 등 부수 수정도 사전 고지 없이는 금지).
- 다른 문서·테이블이 이 문단을 참조할 가능성이 있으면(수치, 시스템 규칙 변경 등) explore 스킬의 변경 영향도 분석을 제안한다.

## (c) 예외처리 검수

`references/exception-review.md`의 체크리스트를 사용한다. 요약:
1. 검수 대상 시스템의 문단을 읽는다.
2. 체크리스트 항목별로 "명시됨(인용) / 누락 / 모호"를 판정한다.
3. 누락·모호 항목마다 **구체적 제안 문안**을 함께 제시한다.
4. 리포트만 출력한다 — 문서 반영은 사용자가 요청할 때 (b) 절차로 진행한다.

## (d) 새 기획서 작성

`references/new-doc.md` 참조. 요약: 양식 학습 → 구조 확정(사용자 확인) → 초안 → 미리보기 → 승인 → 문서 생성.
