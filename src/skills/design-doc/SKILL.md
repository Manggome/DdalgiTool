# 📝 기획서 쓰기·고치기 (design-doc)

구글 독스 기획서를 조회·수정·검수하고, 팀 양식 그대로 새 기획서를 쓴다.

## 언제 쓰나
기획서를 읽고 질문에 답할 때, 고칠 때, 예외처리 공백을 검수할 때, 새 기획서가 필요할 때.

## 꼭 지킬 규칙
1. **원문 인용**: 기획서를 근거로 답하면 해당 문단을 blockquote 로 그대로 인용하고 문서명·섹션을 밝힌다.
   문서에 없으면 "기획서에 명시되지 않음".
2. **긴 문서는 목차부터**: 약 3천 단어 넘는 문서나 3개 이상 통독은 서브에이전트에 맡긴다.
   탭이 여러 개인 문서는 doc_read 가 탭별 구분선과 함께 전부 읽는다.
3. **새 문서는 양식 복제로**: 빈 문서에 조립하지 않는다 — 양식 문서를 drive_copy 한 뒤
   doc_replace / doc_insert_after 로 채워 서식을 그대로 물려받는다.

## 절차
| 요청 | 흐름 |
|---|---|
| 읽고 답하기 | 대상 문서 특정(모르면 ask_choice) → 필요한 섹션만 읽기 → 인용과 함께 답변 |
| 고치기 | 대상 섹션 읽기 → 수정안 → 변경 전/후 미리보기 → 승인 → 반영 → 다시 읽어 확인 |
| 예외처리 검수 | 대상 시스템 문단 → 체크리스트 대조 → 공백·모순 목록 |
| 새로 쓰기 | 양식·기존 문서 구조 학습 → 초안 미리보기 → 승인 → 양식 복제 후 채움 → 예시 줄 정리 |
| 댓글·리뷰 반영 | doc_comments 로 미해결 댓글 정리 → 반영안 미리보기 → 승인 → 반영 |

## 결과물
답변(인용+출처 블록) 또는 수정·생성된 문서 링크(쓰기 후 브라우저로 자동으로 열림).
