# 기획서 (design-doc)

구글 독스 기반 기획서의 조회·수정·검수·신규 작성을 처리한다.

## 절대 규칙
1. **근거 인용 강제**: 기획서 내용을 근거로 답할 때는 반드시 해당 문단을 그대로 인용하고, 문서명과 섹션(제목/위치)을 명시한다. 인용 없는 단정 금지. 문서에 없는 내용은 "기획서에 명시되지 않음"이라고 밝힌다.
2. **수정은 diff 미리보기 → 승인 후에만**: 독스 쓰기 API 호출 전에 반드시 변경 전/후 diff를 보여주고 사용자의 명시적 승인을 받는다. 승인 없이 쓰기 금지.
3. **전체 스캔 금지**: 문서 목록/인덱스 카탈로그에서 대상 문서를 먼저 분류하고, 필요한 문서만 조회한다. 긴 문서(약 3천 단어 초과)나 3개 이상 문서의 통독은 서브에이전트로 격리하고 요약+인용만 받아온다.

## 작업 유형별 진입점

| 요청 | 절차 |
|---|---|
| (a) 읽고 답변 | 대상 문서 특정 → 해당 섹션만 읽기 → 인용과 함께 답변 |
| (b) 수정 | 대상 섹션 읽기 → 수정안 작성 → diff 미리보기 → 승인 → 반영 → 결과 확인 |
| (c) 예외처리 검수 | 대상 시스템 문단 읽기 → 체크리스트 대조 → 공백/모순 리포트 |
| (d) 새 기획서 작성 | 참조 양식·유사 기획서 학습 → 구조 추출 → 초안 → 미리보기 → 승인 → 생성 |

상세 절차: `references/workflows.md`
예외처리 검수 체크리스트: `references/exception-review.md`
양식 학습·신규 작성 가이드: `references/new-doc.md`

## 대상 문서 찾기
1. `.ddalgi/project.yaml`의 `google_drive.docs_folder_id`와 로컬 인덱스 카탈로그(문서명·요약 목록)를 먼저 본다.
2. 카탈로그에서 후보를 2~3개로 좁힌 뒤 제목·목차만 조회해 확정한다.
3. 확정 후 필요한 섹션 범위만 읽는다. 문서 전체 덤프는 마지막 수단.

## 답변 형식
- 답변 마지막에 `출처:` 블록으로 문서명, 섹션 제목, (가능하면) 문서 링크를 나열한다.
- 인용은 blockquote로 원문 그대로. 요약과 원문 인용을 구분한다.
