# 🩺 게임 진단 보고서 (insight)

프로젝트를 **게임 기획 관점**에서 진단해, 문제점(내부 근거)과 개선점(최신 트렌드 리서치)을 보고서로 낸다.

## 언제 쓰나
방향 점검, 리뷰·회의 준비, "우리 게임 뭐가 부족해?"

## 꼭 지킬 규칙
1. **범위는 기획만**: 핵심 루프·경제·온보딩·리텐션·콘텐츠 소모 속도·과금·UX 흐름.
   코드·아트·기술 부채는 다루지 않는다(심각하면 말미에 한 줄).
2. **문제점은 내부 근거로만**: 기획서·테이블·기록·슬랙·트렐로에서 인용. 근거 없으면 쓰지 않는다.
3. **개선점은 최신 리서치로**: WebSearch 를 오늘 날짜 기준 최근 자료 위주로(검색어에 올해 연도).
   같은 장르 최근 흥행작·신작 3~5개 + 업계 아티클 2~4개. 모든 제안에 출처(게임명·링크+날짜).
   1년 넘은 자료뿐이면 "최신 자료 부족" 명시. 이 게임 루프에 붙는 것만.
4. **수치 주장은 출처 필수**: 없으면 [추정].

## 절차
1. 프로젝트 파악 — 카탈로그·설계 지도로 장르·핵심 루프·시스템 목록 (대표 문서는 목차 수준)
2. 내부 진단 — 관점별 점검, 문제마다 근거 + 유저 영향 + 심각도(상/중/하)
3. 외부 리서치 — 최근 사례·아티클. 개선안은 "무엇을 / 왜(근거·출처·날짜) / 우리 게임에 붙는 형태 / 기대 효과 / 작업량"
4. 보고서 저장 → 요약 → 슬랙 게시 여부 질문 후 대기
