# 진단 보고서 HTML 형식

파일명: `진단보고서_<프로젝트>_<YYMMDD>.html` — 한 파일 완결(외부 리소스 금지), 시스템 폰트.

## 구조 (순서대로)

1. **헤더**: 프로젝트명 · 생성일 · 조사 범위(읽은 내부 자료 목록, 리서치 기간) · 요약 문장 1줄.
2. **한눈에 보기**: 문제점 상위 3 + 개선점 상위 3을 카드로 (제목·심각도/기대효과 배지·한 줄 설명).
3. **문제점 섹션** (심각도 상→하 정렬):
   - 각 항목: 심각도 배지(상=빨강/중=주황/하=회색) · 제목 · 무엇이 문제인가 · 유저에게 미치는 영향
   - **근거는 접이식** `<details><summary>근거</summary>` — 기획서 문단 인용/테이블 값/슬랙·아카이브 링크
4. **개선점 섹션** (기대효과 큰 순):
   - 각 항목: 제안 제목 · 무엇을 어떻게 (우리 게임 기준 구체 형태) · 기대 효과 · 작업량(상/중/하) 배지
   - **트렌드 근거는 본문에 짧게 + 접이식 상세**: 참고 게임/아티클 이름, 링크, **게시·확인 날짜**
5. **참고 자료**: 조사한 게임·아티클 전체 목록 (링크+날짜). 최신 자료가 부족했으면 그 사실 명시.
6. **각주** (선택): 기획 외 영역에서 발견한 심각한 사항 한 줄씩.

## 스타일

- 상단 sticky 목차(문제점/개선점 앵커). 카드형 레이아웃, 좌측 심각도 색 스트라이프.
- 어두운 배경에서도 무난한 중립 팔레트. 표보다는 카드+배지. 인쇄해도 읽히게.
- 접기 전에는 근거·기술 상세가 보이지 않아야 한다 (비개발 리더도 그대로 읽는 문서).

## 금지

- 근거 없는 문제 제기, 출처 없는 수치, 코드/아트 품질 평가, 유행 나열식 개선안(루프에 안 붙는 것).
