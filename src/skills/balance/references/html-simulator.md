# HTML 시뮬레이터 제작 가이드

파라미터를 조절하며 결과를 즉시 보고 싶은 요청에 사용한다. 단발 질문("이거 몇 초 걸려?")에는 만들지 않는다 — 스크립트 실행으로 충분.

## 필수 구성
1. **실제 데이터 임베드**: 시트에서 export한 실제 데이터를 JS 상수(JSON)로 임베드한다. 예시 데이터 임의 생성 금지. 임베드 시점(조회 일시)을 데이터 옆에 주석·화면 양쪽에 표기한다.
2. **계산은 전부 JS**: 코드에서 추출한 수식을 JS 함수로 이식하고, 원본 출처를 함수 위 주석으로 명기한다. 반올림 방식을 원본 그대로 재현한다.
3. **출처 패널**: 페이지 하단에 고정 섹션으로 수식 출처(파일:라인), 데이터 출처(시트·탭·조회일), 가정 목록을 표시한다.
4. **검산 표시**: 알려진 케이스 1개의 기대값과 시뮬레이터 계산값을 비교해 페이지 로드 시 일치 여부를 표시한다 (이식 오류 감지용).

## UI 구성 권장
- 좌측(또는 상단): 파라미터 입력 — 슬라이더+숫자 입력 병행, 테이블 원본값으로 리셋 버튼.
- 우측(또는 하단): 결과 — 표 + 간단한 차트(외부 라이브러리 금지, SVG/canvas 직접 그리기).
- 원본 테이블 값과 달라진 파라미터는 시각적으로 표시(색상)해 "현재 라이브 값이 아님"을 명확히 한다.
- 몬테카를로가 필요하면 시행 횟수 입력을 노출하고 기본값은 1만 회(브라우저 성능 고려), 시드 고정 옵션.

## 게시 절차
1. 스크래치패드에 HTML 작성.
2. 임베드된 데이터의 행 수·조회 범위를 사용자에게 보고.
3. Artifact로 게시 (게시 자체는 비공개 시작이므로 승인 불필요하나, 슬랙 공유 등 배포는 승인 필요 — archive 스킬 규칙).
4. 데이터가 바뀌면 시뮬레이터는 낡는다 — "시트 기준 YYYY-MM-DD 스냅샷"임을 사용자에게 고지.

## 주의
- 시뮬레이터의 결론(밸런스 판단)을 채팅으로 보고할 때도 simulation.md의 보고 형식(출처 블록)을 따른다.
- 시뮬레이터에서 찾은 좋은 수치를 테이블에 반영하는 것은 data-table 수정 절차로만 한다.
