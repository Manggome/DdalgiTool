# 밸런스 시뮬레이션 상세

## 1. 수식 확보

### 코드에서 추출 (우선)
- project.yaml의 `table_code_mappings`와 unity `project_path`를 기준으로 관련 스크립트를 찾는다 (예: `DamageCalculator.cs`, `*Formula*`, `*Stat*`).
- 계산 관련 메서드만 읽는다. 클래스 전체 통독 금지.
- 추출한 수식은 **파일 경로와 라인 범위**를 기록한다: `Assets/Scripts/Combat/DamageCalculator.cs:42-58`.
- C# 정수 나눗셈, `Mathf.Floor` vs `Round`, 연산 순서 등 반올림 지점을 그대로 재현한다 — 시뮬레이션 언어로 옮길 때 가장 흔한 오류 지점.

### 기획서에서 추출 (코드가 없을 때)
- 수식 문단을 그대로 인용하고 "코드 미구현/미확인" 표시.
- 기획서와 코드 둘 다 있고 서로 다르면: 계산은 코드 기준으로 하되, 차이를 표로 보고하고 어느 쪽이 맞는지 사용자에게 확인.

## 2. 데이터 확보
- data-table 규칙 준수: 필요한 시트의 필요한 컬럼만 CSV export → 스크래치패드 저장.
- 시뮬레이션 스크립트는 이 CSV를 **파일에서 로드**한다. 수치를 프롬프트에서 코드로 손 복사하지 않는다 (전사 오류 방지).

## 3. 시뮬레이션 코드 작성

### 기본 골격
```python
# 출처 주석 필수
# 수식: Assets/Scripts/Combat/DamageCalculator.cs:42-58
# 데이터: MonsterTable > Balance 탭, PlayerStatTable > Main 탭 (2026-08-28 조회)
import csv, math

def damage(atk, dfn, skill_mult):
    # C# 원본: Mathf.Floor(atk * skill_mult * (100 / (100 + def)))
    return math.floor(atk * skill_mult * (100 / (100 + dfn)))
```

### 검증 패턴
- **TTK/DPS**: 레벨별·구간별 처치 시간 표. 목표 구간(기획서 명시값)이 있으면 이탈 행 강조.
- **성장 곡선**: 레벨별 필요 경험치/전투력 증가율을 표·구간 배율로 출력. 급락/역전 구간 검출.
- **경제 순환**: 획득량 vs 소비량 누적 시뮬레이션, N일차 잔고.
- **확률 검증**: 기대값은 해석적으로(코드로) 계산, 분산·천장 체감은 몬테카를로(시행 횟수 명시, 기본 10만 회, 시드 고정).

### 결과 신뢰성
- 스크립트에 알려진 케이스 1~2개의 검산(assert)을 넣는다 — 기획서에 예시 계산이 있으면 그것으로.
- 실행 오류·NaN·무한루프(예: 데미지 0으로 TTK 무한)는 숨기지 말고 그 자체를 발견으로 보고한다.

## 4. 보고 형식

```
# 밸런스 검증: <주제>

## 결과
<핵심 표/수치 — 스크립트 출력에서만 가져옴>

## 발견
- <목표 대비 이탈, 역전 구간, 코드↔기획서 불일치 등>

## 출처
- 수식: <파일:라인> 또는 <문서명 - 섹션>
- 데이터: <시트명 > 탭 ! 범위> (조회 시각)
- 가정: <목록. 없으면 "없음">
- 스크립트: <스크래치패드 경로> (재실행 가능)
```

- 결과가 크면(수백 행) 요약 통계 + 이상 구간만 보고하고 전체는 CSV로 저장해 경로를 알려준다.
- "밸런스가 좋다/나쁘다" 판단은 기획서의 목표 수치가 근거일 때만 단정한다. 목표가 없으면 관찰 사실만 보고하고 판단 기준을 되묻는다.
