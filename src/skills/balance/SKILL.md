# 밸런스 (balance)

데이터 테이블·코드 수식을 근거로 시뮬레이션 코드를 생성·실행하여 밸런스를 검증한다.

## 절대 규칙
1. **LLM은 수치를 직접 계산하지 않는다.** 암산·추정으로 결과 수치를 내는 것 금지. 모든 계산은 스크립트를 작성해 실행하고, 그 출력만 인용한다. (자릿수 어림 등 계산 방향 판단은 허용하되 최종 수치는 반드시 코드 실행 결과.)
2. **수식은 코드가 진실**: 데미지 공식 등은 기획서보다 유니티 코드(C#)의 실제 구현을 우선 확인한다. 기획서와 코드가 다르면 그 차이를 반드시 보고한다.
3. **결과에 수식·데이터 출처 명시**: 사용한 수식(코드 파일·라인 또는 기획서 섹션), 데이터(시트·범위), 가정을 결과와 함께 표기한다.
4. **가정은 명시적으로**: 데이터·코드에 없는 값(플레이어 스킬 사용 패턴 등)을 가정해야 하면, 가정 목록을 먼저 제시하고 확인받는다.

## 절차 요약
1. **수식 확보**: 매핑 선언(project.yaml)·explore 스킬로 관련 C# 코드를 찾아 계산 로직을 읽는다. 없으면 기획서의 수식 섹션 사용.
2. **데이터 확보**: data-table 스킬 규칙대로 필요한 컬럼·행만 CSV로 export.
3. **시뮬레이션 코드 작성·실행**: 스크래치패드에 스크립트(Node/Python) 작성 → 실제 데이터 로드 → 실행 → 결과 수집.
4. **보고**: 결과 표/요약 + 수식 출처 + 데이터 출처 + 가정 목록.

상세(수식 추출, 검증 패턴, 몬테카를로 등): `references/simulation.md`
HTML 시뮬레이터 제작: `references/html-simulator.md`

## HTML 시뮬레이터
파라미터를 바꿔가며 보고 싶어 하는 요청("~바꿔가면서 보고 싶어", "시뮬레이터 만들어줘")에는 실제 테이블 데이터를 JS에 임베드한 인터랙티브 HTML을 만든다. 계산은 전부 JS로 수행하고, HTML 한 파일을 **작업 폴더에** 저장한다 — 파일이 생기면 앱 오른쪽 HTML 패널이 자동으로 열리므로 브라우저를 따로 띄우지 않는다. 데이터 출처·수식 출처를 페이지 안에 명기한다.

## 수치 반영
시뮬레이션 결과로 테이블 수정을 원하면 data-table 스킬의 수정 절차(미리보기→승인)로 넘어간다. 밸런스 스킬이 직접 시트를 쓰지 않는다.
