# 데이터 테이블 (data-table)

구글 시트 기반 게임 데이터 테이블의 조회·수정·검수·신규 작성을 처리한다.

## 절대 규칙
1. **시트 전체 읽기 금지**: 항상 (1) 스키마(헤더 행 + 행 수)를 먼저 조회 → (2) 필요한 컬럼·행 범위만 쿼리한다. "전부 보여줘"류 요청도 행 수를 먼저 확인하고 많으면(수백 행 이상) 조건을 되묻는다.
2. **수정은 미리보기 → 승인 후에만**: 변경될 셀의 전/후 값을 표로 보여주고 명시적 승인 후 쓰기. 승인 없이 시트 쓰기 API 호출 금지.
3. **출처 명시**: 답변에 시트명·탭명·행 범위(예: `MonsterTable!A15:F15`)를 명시한다.
4. **대량 검수는 코드로**: 수백 행 이상의 검수·집계는 LLM이 눈으로 훑지 않는다. 데이터를 CSV로 내려받아 스크립트로 검사하고 결과만 읽는다.

## 작업 유형별 진입점

| 요청 | 절차 |
|---|---|
| (a) 읽고 답변 | 대상 시트·탭 특정 → 헤더 조회 → 필요한 행만 쿼리 → 출처와 함께 답변 |
| (b) 수정 | 현재 값 조회 → 변경 전/후 표 미리보기 → 승인 → 반영 → 재조회 확인 |
| (c) 오류 검수 | 스키마 파악 → 검수 스크립트 실행 → 리포트 (`references/validation.md`) |
| (d) 새 테이블 작성 | 기획서 근거 확보 → 스키마 제안 → 승인 → 데이터 채움 → 미리보기 → 생성 |

상세 절차: `references/workflows.md`
검수 항목·스크립트 패턴: `references/validation.md`

## 대상 시트 찾기
1. `.ddalgi/project.yaml`의 `google_drive.sheets_folder_id`와 인덱스 카탈로그(시트명·탭·컬럼 목록)를 먼저 본다.
2. 테이블명↔코드 매핑(`table_code_mappings`)이 있으면 그 선언을 신뢰한다.

## 수정 시 추가 주의
- ID 컬럼 변경, 행 삭제, 참조되는 값 변경 시 explore 스킬의 변경 영향도 분석을 먼저 제안한다.
- **수식 컬럼 규칙**: 수정 전 `sheet_read(formulas=true)` 로 대상 컬럼에 수식이 있는지 확인한다.
  수식이 있는 컬럼은 값으로 덮어쓰지 않고, 새 행을 채울 때도 같은 수식 패턴(행 번호만 조정)으로 쓴다.
- **룩업 null → localize 신설**: VLOOKUP 등 룩업으로 채워지는 name/desc 류 컬럼이 비어 있거나
  #N/A·null 이면 원본 localize(현지화) 테이블에 키가 없는 것이다 — 룩업 셀을 값으로 덮지 말고,
  localize 테이블에 신규 키 행 추가를 제안해 승인받아 진행한다.
- 파일·행 삭제는 하지 않는다. 삭제가 필요해 보이면 이름 앞에 `[삭제용] ` 을 붙여 표시만 한다.
