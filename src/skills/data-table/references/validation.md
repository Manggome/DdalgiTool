# 테이블 오류 검수

## 원칙
- 검수는 **스크립트로 결정적으로** 수행한다. LLM이 행을 눈으로 훑으며 판단하지 않는다.
- 절차: 시트를 CSV로 export → 스크래치패드에 저장 → 검사 스크립트(Node/Python) 작성·실행 → 위반 행만 리포트.
- 여러 시트 간 참조 검사는 관련 시트의 **키 컬럼만** export한다.

## 검수 항목

### 1. 중복 ID
- 키 컬럼(보통 `Id`)의 중복 검출. 복합 키 테이블은 조합 중복 검사.
- 대소문자만 다른 ID, 앞뒤 공백이 붙은 ID도 별도 리포트 (사실상 중복 위험).

### 2. 참조 누락 (외래키)
- 다른 테이블의 ID를 참조하는 컬럼(예: `DropItemId` → ItemTable.Id)이 실제 존재하는 값인지.
- 참조 관계는 (1) project.yaml의 `table_code_mappings`/컬럼명 규칙(`~Id` 접미사), (2) 사용자 지정으로 파악한다. 추정한 참조 관계는 리포트에 "추정"으로 표기.
- 역방향도 확인: 코드 enum에는 있는데 테이블에 없는 ID (explore 스킬의 정합성 검사와 연계).

### 3. 타입 불일치
- 숫자 컬럼에 문자열/빈 값, 불리언 컬럼에 그 외 값, 날짜 형식 불일치.
- 숫자 컬럼의 타입은 열 전체 다수 형식을 기준으로 이탈 값을 찾는다.
- 천 단위 콤마, 전각 숫자, 보이지 않는 공백 문자 등 흔한 시트 오염 패턴 검사.

### 4. 범위 이탈
- 음수 금지 컬럼(HP, 가격 등)의 음수, 확률 컬럼의 0~1(또는 0~100) 이탈, 확률 그룹 합계 검증.
- 레벨·등급 등 enum성 컬럼의 허용값 이탈.
- 명시된 규칙이 없으면 통계적 이상치(다른 행 대비 자릿수가 다른 값 등)를 "의심"으로만 리포트.

### 5. 구조 문제
- 빈 행/빈 필수 컬럼, 헤더와 데이터 열 수 불일치, 병합 셀, 중간에 끼어든 주석 행.

## 스크립트 패턴

```python
import csv, collections
rows = list(csv.DictReader(open(PATH, encoding='utf-8')))
# 중복 ID
dup = [k for k, c in collections.Counter(r['Id'] for r in rows).items() if c > 1]
# 타입: int 기대 컬럼
bad = [(i+2, r['Hp']) for i, r in enumerate(rows) if not r['Hp'].strip().lstrip('-').isdigit()]
# 참조: item_ids = set(ItemTable의 Id 컬럼)
missing = [(i+2, r['DropItemId']) for i, r in enumerate(rows) if r['DropItemId'] and r['DropItemId'] not in item_ids]
```
행 번호 리포트는 헤더 포함 실제 시트 행 번호(+2 보정)로 출력한다.

## 리포트 형식

```
# 테이블 검수: <시트명> > <탭명> (총 N행)

## 요약: 오류 N건 / 의심 N건 / 통과 항목: 중복ID, ...

## 오류 (수정 필요)
| # | 항목 | 위치 | 내용 |
|---|------|------|------|
| 1 | 중복 ID | 15행, 203행 | MON_0042 중복 |

## 의심 (확인 필요)
| 1 | 범위 이탈 의심 | 88행 Atk | 9999 — 다른 행 평균 대비 50배 |
```

- 리포트 후 "수정할까요?"를 묻고, 수정은 (b) 절차(미리보기→승인)로 진행한다. 검수가 자동으로 수정으로 이어지지 않는다.
