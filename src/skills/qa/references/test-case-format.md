# QA 테스트 케이스 형식·작성 요령

## 케이스 필드

| 필드 | 설명 |
|---|---|
| ID | `TC-<카드 축약>-NN` (카드 내 고유) |
| 우선순위 | P0~P3 (`priority.md` 기준) |
| 분류 | 정상 / 경계 / 예외 / 상호작용 / UI·연출 |
| 사전 조건 | 계정 상태, 데이터 조건 (테이블 행 근거로 구체적 ID·수치 명시) |
| 절차 | 번호 매긴 실행 단계 — 테스터가 그대로 따라할 수 있게 |
| 기대 결과 | 근거 문서가 정의한 결과. 수치는 테이블/수식 출처 명기 |
| 근거 | 기획서 문단 인용(blockquote) / `시트 > 탭 ! 범위` / `파일:라인` |

## 작성 요령

- **구체적 데이터 사용**: "몬스터를 잡는다"가 아니라 "MON_0042(고블린, HP 350 — MonsterTable!C42)를 잡는다". 테스터가 조건을 재현할 수 있어야 한다.
- **기대 결과에 수치가 들어가면** 계산이 필요한 값은 balance 스킬 원칙대로 스크립트로 산출하고 출처를 단다. 암산 수치 금지.
- **코드 분기를 근거로 한 케이스**: 코드에서 발견한 분기(예: `if (level >= MaxLevel)`)는 기획서에 대응 문단이 있는지 교차 확인한다. 코드에만 있는 동작은 근거에 "코드 전용 — 기획서 미기재"를 표기 (기획 공백 후보).
- **케이스 수보다 커버리지**: 같은 분기를 다른 숫자로 반복하는 케이스를 늘리지 않는다. 경계값은 경계 직전/경계/직후 3점이면 충분.

## 도출 순서

1. **정상 경로**: 기획서의 주 시나리오 그대로 1~2건.
2. **경계값**: 근거 자료의 모든 수치 경계 (최소/최대 레벨, 재화 0/딱 맞음/초과, 인벤토리 가득 참…).
3. **예외 경로**: design-doc의 `exception-review.md` 체크리스트를 카드 시스템에 대입 — 자원 부족, 시간 경계, 이탈(취소/강제종료), 동시성.
4. **상호작용**: explore의 변경 영향도 방식으로 이 시스템과 얽힌 시스템 1단계를 찾아 조합 케이스.
5. **UI·연출**: 기획서에 명시된 메시지·연출 문구 확인 케이스 (문구 원문 인용).

## 리포트 형식

```
# QA 케이스: <트렐로 카드명> (카드 링크)

## 근거 자료
- "장비 강화 기획서" 3~4장 / UpgradeTable > Main / Upgrade.cs

## 테스트 케이스 (N건: P0 n, P1 n, P2 n, P3 n)
### [P0] TC-UPG-01 (예외) 강화 중 앱 강제 종료
- 사전 조건: ...
- 절차: 1. ... 2. ...
- 기대 결과: ...
- 근거: > "강화 진행 중 접속이 종료되면 재화는 차감되지 않는다" — 장비 강화 기획서 5.1

## 기획 공백 (기대 결과 정의 불가 — 기획 확인 필요)
1. 강화 성공 연출 중 이벤트 종료 시 배율 적용 여부 — 기획서·코드 모두 미정의

## [추정] 케이스 (근거 없음 — 관례 기반)
...
```

- 기획 공백 항목은 design-doc의 예외처리 검수 제안 문안 형식으로 이어서 제안할 수 있다.
- 트렐로/시트 게시 시: 게시될 내용과 위치를 미리보기로 확인받은 후 실행. 작업 로그 기록.
