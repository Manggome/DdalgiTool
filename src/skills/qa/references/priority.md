# QA 우선순위 기준 (P0~P3)

두 축으로 판단한다: **발생 시 피해** × **발생 가능성/노출 빈도**.

## P0 — 즉시 차단급 (릴리스 블로커)
- 재화·결제·보상이 잘못 지급/차감되거나 복제·소실될 수 있는 경로
- 데이터 유실, 진행 불가(소프트락), 크래시가 예상되는 경로
- 확률형 아이템 고지 등 법적·정책 요건 관련 동작
- 판단 근거 예: 기획서가 "차감되지 않는다"고 명시한 복구 경로, 결제 연동 분기

## P1 — 핵심 기능 정상 동작
- 카드가 다루는 기능의 주 시나리오(정상 경로)와 주요 경계값
- 잘못되면 유저 다수가 즉시 체감하는 수치 오류 (데미지 공식, 드랍률 적용)
- 다른 시스템과의 핵심 상호작용

## P2 — 보조 경로·드문 예외
- 발생 빈도가 낮은 예외 경로 (희귀한 타이밍, 특수 상태 조합)
- 잘못돼도 우회 가능하거나 피해가 국소적인 동작
- 보조 UI 흐름 (취소, 뒤로가기, 재진입)

## P3 — 코스메틱
- 문구·오탈자·정렬·연출 타이밍 등 기능에 영향 없는 항목
- 극단적으로 인위적인 조건에서만 발생하는 문제

## 조정 규칙
- 같은 케이스라도 **이벤트/출시 직전** 기능이면 한 단계 올린다 (노출 확실).
- 기획 공백으로 분류된 항목은 우선순위를 매기지 않는다 — 기대 결과가 없으면 테스트가 아니다. 대신 공백 자체의 확인 시급도를 상/중/하로 표기.
- 애매하면 낮은 쪽이 아니라 높은 쪽으로 — 단, P0은 위 정의에 해당할 때만. P0 인플레이션은 P0의 의미를 죽인다.
- 카드 하나에서 P0가 3건을 넘으면 케이스 문제가 아니라 설계 리스크다 — 요약에서 별도로 경고한다.
