# QA (qa)

트렐로 카드 단위로 관련 기획서·데이터 테이블·코드를 근거로 테스트 케이스를 작성하고, 예외처리 공백을 검토하며, P0~P3 우선순위를 매긴다.

## 절대 규칙
1. **모든 케이스에 근거 인용 강제**: 각 테스트 케이스는 근거(기획서 문단 인용 / 테이블 행 / 코드 파일:라인) 중 최소 하나를 명시한다. 근거 없는 케이스는 `[추정]` 태그를 달고 별도 섹션으로 분리한다.
2. **근거 수집도 토큰 절약 규칙 준수**: 카드와 관련된 문서·시트·코드를 카탈로그/매핑에서 먼저 분류하고 필요한 부분만 읽는다. 여러 문서 통독은 서브에이전트로 격리.
3. **트렐로 쓰기(카드에 체크리스트/코멘트 첨부)는 미리보기 → 승인 후에만.** 시트로 출력할 때도 동일.

## 절차 요약
1. **카드 파악**: 대상 트렐로 카드의 제목·설명·코멘트를 읽는다. 카드가 여러 개면 카드별로 독립 수행.
2. **근거 수집**: 카드가 다루는 시스템의 (1) 기획서 관련 섹션 (2) 관련 테이블 스키마+대표 행 (3) 매핑된 코드의 분기 지점을 수집한다.
3. **케이스 설계**: 정상 경로 → 경계값 → 예외 경로 → 상호작용 순으로 도출. design-doc 스킬의 `exception-review.md` 체크리스트를 예외 케이스 소스로 재사용한다.
4. **공백 검토**: 기획서가 정의하지 않은 예외 상황은 테스트 케이스가 아니라 **기획 공백**으로 분리 리포트한다 ("기대 결과를 정할 수 없음").
5. **우선순위 분류**: P0~P3 기준(`references/priority.md`)으로 각 케이스에 부여.
6. **출력**: 채팅 리포트 기본. 요청 시 트렐로 체크리스트/구글 시트로 (승인 후) 게시.

케이스 형식·작성 요령: `references/test-case-format.md`
우선순위 기준: `references/priority.md`
