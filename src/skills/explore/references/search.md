# 횡단 탐색 상세

## 절차

1. **질문 분해**: 무엇을 찾는가 — 결정 경위? 확정 스펙? 수치? 담당자? 시점? 이에 따라 1순위 소스를 정한다.

   | 찾는 것 | 1순위 | 2순위 |
   |---|---|---|
   | 왜 이렇게 결정됐나 | archive/decisions/ (ADR) | 슬랙 검색 |
   | 논의·맥락·뒷이야기 | 슬랙 | 트렐로 카드 코멘트 |
   | 확정 스펙·규칙 | 구글 독스 | 코드 |
   | 수치·데이터 | 구글 시트 | 코드 상수 |
   | 실제 동작 | 유니티 코드 | 독스 |
   | 언제/누가 바꿨나 | 깃 로그(git log -S) | 슬랙 |
   | 작업 상태·담당 | 트렐로 | 슬랙 |

2. **카탈로그 조회**: 선택한 소스의 카탈로그 항목(채널 목록·문서 제목·시트 목록)에서 후보를 좁힌다.
3. **표적 조회**: 후보만 검색 API/부분 읽기로 조회한다.
   - 슬랙: 검색 API로 키워드 검색 → 히트 스레드만 읽기. 채널 히스토리 전체 페이지네이션 금지. 90일 제한으로 없을 수 있음 → archive 백업(`archive/slack/`)도 검색.
   - 깃: `git log --oneline -S"키워드"` / `git log -- <경로>` → 관심 커밋만 `git show`. 전체 diff 덤프 금지.
   - 코드: 파일명·심볼 grep → 히트 파일의 관련 부분만 읽기.
   - 트렐로: 보드 검색 → 카드 제목 매칭 → 해당 카드의 설명·코멘트만.
4. **확장 판단**: 1순위에서 못 찾으면 2순위로 확장. 3개 소스에서 못 찾으면 중간 보고하고 계속 찾을지 확인받는다.

## 서브에이전트 격리
- 격리 대상: 스레드 5개 이상 읽기, 파일 5개 이상 읽기, 문서 통독.
- 지시 형식: "다음 <소스 목록>에서 <질문>의 답을 찾아라. 발견마다 원문 인용(짧게)과 정확한 출처(링크/파일:라인/커밋)를 붙여 반환하라. 못 찾으면 어디를 봤는지 목록으로 반환하라."
- 서로 다른 소스는 병렬 서브에이전트로 동시에 조사해도 된다 (단, 1순위에서 찾을 확률이 높으면 순차가 더 싸다 — 판단해서 선택).
