# 변경 영향도 분석

"X를 바꾸면(또는 지우면) 무엇이 영향받는가"에 대한 체계적 조사.

## 절차

1. **대상 정규화**: 변경 대상을 식별자 목록으로 만든다.
   - 테이블 값 변경 → 시트명, 탭, 컬럼명, (특정 행이면) ID 값
   - 시스템 규칙 변경 → 시스템명 + 관련 용어(국문/영문/코드 심볼명 모두)
   - ID 삭제/개명 → 해당 ID 문자열
2. **매핑 선언 확인**: project.yaml의 `table_code_mappings`에서 대상 테이블과 연결된 코드 파일을 얻는다. 이것이 가장 신뢰도 높은 간선.
3. **소스별 조사** (순서대로, 각각 표적 검색만):
   - **코드**: 유니티 프로젝트에서 식별자 grep (`grep -rn "MON_0042" Assets/ --include=*.cs` + ScriptableObject/프리팹 참조가 의심되면 `*.asset`, `*.prefab`도). 히트한 파일:라인 기록.
   - **시트**: 다른 테이블에서 이 ID/컬럼을 참조하는 곳 — 참조성 컬럼(`~Id`)만 export해 검사.
   - **기획서**: 인덱스 카탈로그에서 시스템명·ID 언급 문서 검색 → 해당 문서의 언급 섹션만 확인.
   - **트렐로/슬랙**: 진행 중 작업이 있는지 카드 검색 (선택적 — 사용자가 "팀 상황까지" 원할 때).
4. **간접 영향 1단계 추적**: 직접 영향받는 코드가 다시 큰 시스템에 물려 있으면(예: DropItemId → 보상 지급 전체) 1단계까지만 언급하고, 더 깊은 추적은 필요 시 사용자 확인 후.

## 대량 grep 격리
- 코드베이스 grep과 히트 파일 확인은 서브에이전트로 격리 가능. 반환 형식: `파일:라인 — 한 줄 맥락`.

## 리포트 형식

```
# 변경 영향도: <대상> (예: MonsterTable.Id "MON_0042" 삭제)

## 요약: 테이블 N곳 / 코드 N곳 / 기획서 N곳 — 위험도: 높음/중간/낮음

## 테이블
- DropTable > Main ! B12, B44 — MonsterId로 참조 중 (삭제 시 참조 깨짐)

## 코드
- Assets/Scripts/Data/MonsterId.cs:17 — enum 멤버 (매핑 선언 기준)
- Assets/Scripts/Quest/QuestTargets.cs:88 — 하드코딩 참조 ⚠

## 기획서
- "사냥터 개편 기획서" > 3.2 스폰 목록 — 명시 언급

## 확인하지 못한 것
- 프리팹/씬 내 직렬화 참조 (asset 텍스트 검색 한계)
```

- 위험도 판정 기준: 참조가 깨지는 곳(오류 유발)이 있으면 높음, 수치만 달라지면 중간, 문서 언급뿐이면 낮음.
- 하드코딩 참조 발견은 ⚠ 표시 — 매핑 선언에 없는 결합이므로 별도 강조.
- 이 분석은 읽기 전용이다. 후속 수정은 각 스킬(data-table/design-doc)의 승인 절차로 진행.
