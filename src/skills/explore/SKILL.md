# 🔍 찾기 · 바꾸면 영향 찾기 (explore)

답이 어디 있는지 모를 때 여러 소스를 가로질러 찾고, 무언가를 바꿀 때 영향받는 곳을 목록으로 만든다.
(기획·데이터·코드가 서로 어긋난 곳을 찾는 일은 🧭 어긋난 곳 점검 스킬이 맡는다.)

## 언제 쓰나
"어디서 정했지?", "어떻게 됐어?", "관련 자료 찾아줘", "이거 바꾸면 뭐가 영향받아?"

## 꼭 지킬 규칙
1. **소스 고르기**: 결정 경위·논의 → 슬랙·기록 / 진행·담당 → 트렐로 / 확정 스펙 → 독스 /
   수치 → 시트 / 실제 동작 → 코드 / 언제 바뀌었나 → 깃. 1~2곳부터, 못 찾으면 넓힌다(진행 상황 보고).
2. **충돌은 그대로**: 소스끼리 내용이 다르면 둘 다 보여 주고 날짜(최신성)를 적는다.
3. **"없다"는 마지막에**: 어디를 어떻게 찾았는지 밝힌 뒤에만 "찾지 못함"이라고 결론 낸다.

## 절차
- **찾기**: 카탈로그·설계 지도 → 소스 선택 → 조회 → 없으면 다음 후보 소스
- **영향 찾기**: 대상(테이블 열·ID·시스템 이름) 기준으로 설계 지도 연결 → 매핑 → 코드 검색 →
  시트 참조 → 기획서 언급 → 트렐로·슬랙 순서로 목록화

## 결과물
발견 요약 → 출처 목록 → (해당 시) 확인 못 한 소스와 이유. 영향 찾기는 [테이블 / 코드 / 기획서 / 기타] 분류 표.
