# 탐색 (explore)

슬랙·트렐로·드라이브·코드·깃을 가로지르는 탐색, 변경 영향도 분석, 테이블↔코드 정합성 검사를 수행한다.

## 절대 규칙
1. **카탈로그 우선**: 어떤 소스든 조회 전에 인덱스 카탈로그(문서/시트/채널/보드 목록과 요약)를 먼저 보고, 답이 있을 소스를 **선택**한 뒤 그 소스만 조회한다. 전 소스 순차 풀스캔 금지.
2. **소스 선택 휴리스틱**: 결정 경위·논의 → 슬랙, 아카이브 ADR / 작업 현황·담당 → 트렐로 / 확정 스펙 → 독스 / 수치 → 시트 / 실제 동작 → 코드 / 변경 이력·시점 → 깃.
3. **대량 읽기는 서브에이전트 격리**: 슬랙 스레드 다량, 코드 다수 파일, 문서 통독은 서브에이전트에 맡기고 "발견 + 정확한 출처"만 받는다.
4. **출처 명시**: 모든 발견에 출처(채널·스레드 링크, 카드, 문서 섹션, 파일:라인, 커밋 해시)를 붙인다. 소스 간 정보가 충돌하면 충돌을 그대로 보고하고 최신성(날짜)을 표기한다.

## 3대 작업

### 1. 횡단 탐색 ("~어디 있어?", "~어떻게 됐어?")
카탈로그 → 소스 1~2개 선택 → 조회 → 못 찾으면 다음 후보 소스로 확장(사용자에게 진행 보고). 상세: `references/search.md`

### 2. 변경 영향도 분석 ("X 바꾸면 뭐가 영향받아?")
대상 식별자(테이블 컬럼/ID/시스템명)를 기준으로 project.yaml 매핑 → 코드 grep → 시트 참조 → 기획서 언급 → 트렐로/슬랙 순으로 영향 목록을 만든다. 결과는 [테이블/코드/기획서/기타] 분류 리스트. 상세: `references/impact-analysis.md`

### 3. 테이블↔코드 정합성 검사
`.ddalgi/project.yaml`의 `table_code_mappings` 선언을 기반으로 **결정적으로**(스크립트) 수행한다: 시트 키 컬럼 export ↔ 코드 enum/상수 파싱 → 양방향 차집합 리포트. 선언되지 않은 매핑은 추정으로 검사하지 않는다 — 선언 추가를 제안한다. 상세: `references/consistency-check.md`

## 보고 형식
발견 요약 → 출처 목록 → (해당 시) 확인 못 한 소스와 이유. "없다"는 결론은 어디를 어떻게 찾았는지 밝힌 뒤에만 낸다.
